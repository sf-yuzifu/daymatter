# 事件数据模型

本文说明当前事件文件、日期计算、排序与表盘规则，供维护者和插件开发者参考。同步行为见[同步与兼容说明](sync-compatibility.md)，开发命令见[项目 README](../README.md)。

## 1. 文件结构

事件保存在 `events.json`，使用版本 2 的对象结构。示例：

```json
{
  "version": 2,
  "revision": 1,
  "primaryId": "event-example",
  "watchfacePending": false,
  "sortMode": "created",
  "events": [
    {
      "id": "event-example",
      "name": "生日",
      "date": "2000-02-29",
      "on_index": true,
      "IFStaringDay": false,
      "repeat": "yearly",
      "displayUnit": "days",
      "pinned": false,
      "sortOrder": 0,
      "category": "birthday",
      "archived": false
    }
  ]
}
```

示例 ID 仅用于说明。事件由应用分配稳定 ID，排序、筛选和分页后的修改 / 删除仍按 ID 定位。

### 顶层字段

| 字段 | 含义 |
| --- | --- |
| `version` | 数据格式版本，当前为 `2` |
| `revision` | 提交修订号，用于关联保存结果与列表快照 |
| `primaryId` | 表盘主事件 ID；空字符串表示没有主事件 |
| `watchfacePending` | 表盘派生文件需要补写的标记 |
| `sortMode` | `created` / `near` / `manual`，缺省为 `created` |
| `events` | 事件数组，上限 200 条；数组位置保留创建顺序与旧协议下标含义 |

### 事件字段

| 字段 | 类型 / 取值 | 含义或缺省行为 |
| --- | --- | --- |
| `id` | 字符串 | 稳定身份，旧记录迁移时补齐 |
| `name` | 字符串 | 事件名称 |
| `date` | `YYYY-MM-DD` | 原始公历日期，年份范围 0001～9999 |
| `on_index` | 布尔 | 是否在首页展示，与表盘主事件独立 |
| `IFStaringDay` | 布尔 | 是否计入起始日；拼写沿用既有数据格式 |
| `themeColor` | 既有调色板颜色 | 事件主题色 |
| `repeat` | `none` / `yearly` | 单次 / 年度重复，缺省为 `none` |
| `displayUnit` | `days` / `weeks` / `months` / `years` | 显示偏好，缺省为 `days` |
| `pinned` | 布尔 | 是否置顶，缺省为 `false` |
| `sortOrder` | 非负安全整数 | 手动顺序，旧记录缺省按存储位置补齐 |
| `category` | 见下表 | 缺省为 `uncategorized` |
| `archived` | 布尔 | 是否归档，缺省为 `false` |

| 分类标识 | 显示名称 |
| --- | --- |
| `uncategorized` | 未分类 |
| `birthday` | 生日 |
| `study` | 学习 |
| `life` | 生活 |
| `anniversary` | 纪念日 |

旧记录缺少新增字段时按上述缺省行为读取。修改未提供的字段保留原值，未知事件扩展字段也予以保留；插件解析和传输仍受消息预算限制。

## 2. 名称与日期

- 新建或改名最多 50 个 Unicode 码点；emoji 单码点计 1，组合附加符和 ZWJ 序列分别按码点计数，不按字素簇计数。
- 保存时去除显式 ECMAScript 首尾空白，保留内部空白，不做 Unicode 规范化；`U+0085` 不在该空白集合中。
- 空名称、超长名称和非法 Unicode 输入会被拒绝。
- 旧名称完全不变时允许修改其他字段，不截断旧长名称，也不重新修整其空白。
- 日期归一为 `YYYY-MM-DD`，拒绝不存在的日期，计算不依赖字符串形式的 `new Date()` 解析。
- 计入起始日只影响过去 / 今天的展示：今天为 1 天，未来方向不额外加一天。
- 月份跨度采用月末锚点，例如 1 月 31 日至 3 月 1 日为 1 个月 1 天。

## 3. 年度重复与显示单位

### 农历事件

`calendar` 为 `solar`（缺省）或 `lunar`。农历保存 `lunarDate={year,month,day,leap}`，`date` 保持原始农历日对应的公历日期；换算表版本为 `lunarTableVersion=dm-hko-v1`。农历年范围1900～2100，对应公历1900-01-31～2101-01-28。

农历单次保持固定日期，年度重复按农历月日重新换算；普通月只发生一次，闰月日期无对应闰月时回退普通同月（`lunarLeapPolicy=regularFallback`），三十遇小月使用月末二十九（`lunarShortMonthPolicy=lastDay`）。原始输入必须是真实存在的日期；回退只用于年度派生，不改原始农历字段。超出表范围时显示 `--`，不退回原公历日期倒计时。

编辑页历法使用与显示单位相同样式的选择器，选择公历/农历时保持同一天，腕端日期选择器仅列出当年真实普通/闰月；插件农历输入年月日并单独选择闰月。新保存/备份恢复校验农历与公历映射和表版本。旧端改名保留农历，单独改成不一致公历日期会被拒绝，需新版显式选择历法。

年度重复保留原始 `date`，显示和表盘使用派生发生日：

- 发生年份不早于原始年份；周年数为发生年份减原始年份，首次为 0。
- 当天仍视为本次发生日，次日才滚动到下一年。
- 非闰年的 2 月 29 日按 2 月 28 日发生，闰年恢复 2 月 29 日。
- 超出年份 9999 时不生成非法的下次日期。

`displayUnit` 是每事件独立保存的显示偏好。跨度不足对应单位时回退为天数，但不修改偏好。首页切换单位仅修改当前稳定 ID 的事件。

## 4. 排序、筛选与手动移动

排序模式保存在顶层 `sortMode`，首页与腕端列表共用 `eventOrder` 规则：

| 模式 | 顺序 |
| --- | --- |
| `created` | 按存储数组位置 |
| `near` | 今天及未来按发生日从近到远；过去单次事件放后面，最近过去的优先；年度事件按下次发生日 |
| `manual` | 按 `sortOrder` |

所有模式均优先显示置顶组；同值以存储位置稳定兜底。临近排序依据发生日，不受计入起始日影响。

手动移动只在**相同置顶状态、相同归档状态**的组内进行，不受分类筛选限制、不跨组。移动修改 `sortOrder`，不重排存储数组；成功移动会切换并保存手动模式。

- 腕端前移 / 后移是编辑草稿，保存时与字段变更一起提交，取消不写入。
- 插件移动针对已保存事件；如需使用新草稿字段，应先提交修改，再移动并同步列表核对。
- 独立移动到组边界时返回 `MOVE_BOUNDARY`。

分类与归档筛选只影响显示，是本次页面 / 插件运行状态。腕端列表每页最多 10 条，插件每页最多 8 条；首页最多使用 3 个卡片槽位，并过滤已归档与非首页事件。

## 5. 归档与表盘主事件

### 快捷模板与近期筛选

新增页提供生日（生日分类、年度重复）、考试（学习分类、单次）和纪念日（纪念日分类、年度重复）模板，显示单位默认天。应用模板保留日期和自定义名称；空名称或与任一模板默认名称完全相同的名称替换为新模板名称。只更新草稿，仍可用键盘和日期选择器修改，保存前不写入。自定义选项不撤销已经修改的草稿。

列表显示范围按正常 → 已归档 → 今天事项 → 未来30天循环，复用原分类、排序和分页。今天按发生日等于今天判断，未来30天包含今天至第30天，不含过去单次事件和归档事件；年度事件按派生发生日判断，不受计入起始日展示天数影响。筛选属于运行内状态，不写入事件或改变表盘。

归档不删除事件，也不改变首页开关、原日期、重复规则和显示单位。恢复后保留这些设置。

`primaryId` 与 `on_index`、置顶和排序互相独立：

- 首页开关、置顶与排序不会自动指定表盘主事件。
- 不允许把已归档事件指定为主事件。
- 删除或归档主事件时，按存储顺位选择第一个未归档且首页展示的事件接替；没有候选则清空。
- 恢复归档事件不会自动夺回主事件。
- 插件在修改子页独立设置/取消已保存事件，不提交其他草稿；取消清空主事件，不自动选择替代。取消时核对原主事件 ID，引用已变更则拒绝，需重新同步。

表盘派生文件 `date.txt` 保持既有格式：

```text
名称,YYYY-MM-DD,true/false
```

名称里的逗号、换行与制表符替换为空格。年度事件输出本次 / 下次发生日，显示单位不改变文件格式。

应用提交、页面进入和前台跨午夜时维护派生文件；失败时记录待补写状态。应用退出期间没有可靠后台调度，年度日期需要重新打开应用后更新。

## 6. 存储与失败恢复

存储层串行执行读改写，先写临时文件，再提交正式引用；必要时通过 `.bak` 交换 / 回滚。损坏数据保留 `.bad` 现场。文件不存在可以初始化，损坏或 I/O 错误不能当空列表直接覆盖。

事件提交与表盘文件同步是分项结果：表盘写入失败不代表事件未保存，不应因此重复新增。设备上的文件替换行为仍需实际验证。
