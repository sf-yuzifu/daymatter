# 背景图片与分片传输

## 成品生成

插件进入背景页后，通过握手读取腕端`screenWidth/screenHeight`，提供“读取连接设备屏幕”重读入口。尺寸来自实际设备，不按型号猜测；预览与设备关联，换设备后不能发送旧成品。

- 输出设备原尺寸，单边1～512px，9 Pro为336×480。
- 居中裁剪填满或等比留黑边，圆屏/胶囊边缘由设备裁切。
- PNG≤256KiB，Best压缩与自适应过滤，无损编码合成后的RGB像素；透明合成白底。超限明确拒绝，不减色/缩小或回退JPEG。
- 先裁原图再缩放，避免极端比例产生巨大中间图。
- 选图只生成实际成品预览，确认后才发送；切换处理方式使旧预览失效。

输入JPEG/PNG≤16MiB、单边≤8192px、≤8Mi像素，解码器分配限制64MiB。宿主选图接口一次性返回文件，因此无法限制宿主读取阶段；原始选图数据处理后释放。

## 传输协议

要求`backgroundChunks`、`backgroundChunks24KiB`、`background256KiB`、`backgroundResult`、`requestId`、`mutationResult`能力。未确认则要求升级，不静默改用整包；腕端保留旧`addBG`及3KiB分片接收兼容。

| 消息 | 字段与行为 |
| --- | --- |
| `beginBG` | 请求身份、总`bytes`、FNV-1a `checksum`，预约单飞任务 |
| `backgroundChunk` | 同请求身份、`offset`、Base64 `data` |
| `backgroundAck` | 同请求身份、已写入前沿`next` |
| `finishBG` | 同请求身份，要求完整长度与校验一致后提交 |
| `mutationResult` | 文件与索引最终保存结果，可通过原请求查询 |

请求身份为`sessionId/requestId/deviceId`；deviceId用于关联，不是认证。窗口1，每片≤24576B二进制/32768字符Base64，256KiB最多11片，写入临时文件成功才ACK。偏移连续，上一片重复载荷只重报ACK，冲突拒绝；腕端不拼整图字符串。

每片等待8秒，最多重试2次；重试同一片不重复提交。腕端接收阶段120秒总超时，在途原生写回后结算；完整图提交开始后不按接收超时中断。最终结果未知时查询原请求，不能把事件列表当成背景内容核实。

## 存储与失败恢复

`background.json`保存`{version:1,uri}`，空uri表示默认黑色。首次无索引/备份时迁移旧`bg_<数字>.png/jpg`，之后缓存引用。

临时图片完整写入并校验 → 移动到唯一正式路径 → tmp/bak交换提交索引 → 清理孤立旧图。失败保留旧引用；有效备份可恢复，损坏/I/O不当作空数据覆盖。清理只针对严格背景/临时命名，不删除事件或未知名称文件。

关于页提供确认后恢复默认：先提交空引用再清理。旧图删除失败也不会在重启后复活。

## 内存与兼容边界

腕端传输缓冲主要为当前24KiB字节、当前32KiB字符和上一片32KiB去重字符，JSON/文件API复制与原生解码还会占用内存。PNG文件大小不等于像素内存：336×480 RGBA约630KiB。move兼容复制仍使用3KiB缓冲。

未启用LVGL I8；统一输出PNG。保存回执证明落盘与引用提交，不证明固件图片可显示。真实BLE、append、断连和峰值需按设备验证。

## 验证入口

- `node --test tools/test-background.cjs`：去重、校验、缺片、超时/迟到写回和旧图保护。
- `tools/test-ime.cjs`：实际页面ACK、回执及重复finish。
- 插件`ui/background.rs`和`cross_protocol_tests.rs`：早到/重复ACK及Rust发送器→腕端往返。
- `tools/evaluate-background-transfer.cjs`：历史整包开销测量，仅供对比，不是当前上传流程。

真机复验：横/竖/透明图两种处理方式、预览与腕端一致、上传期间断连/重连、连续上传、恢复默认后重启，以及小内存设备峰值。
