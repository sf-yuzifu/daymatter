# JSON 备份与恢复

备份入口位于 AstroBox 插件「修改」页。请更新快应用和插件，先同步完整腕端列表，再导出或预览恢复。

## 使用流程

1. 点击「同步腕端数据」，取得同设备完整列表。
2. 点击「导出完整 JSON 备份」，选择保存位置。导出所有事件，包括归档事件、稳定 ID、颜色、重复规则、显示单位、置顶、分类、手动顺序和未知扩展，以及排序模式、表盘主事件引用。
3. 点击「选择 JSON 并预览恢复」，选择本工具生成的备份。校验通过后显示事件数量、同 ID 冲突和同名不同 ID。
4. 选择合并或替换；合并时选择同 ID 保留现有记录或使用备份记录。
5. 点击「确认按预览恢复」，等待腕端最终回执，再重新同步列表核对。

完整快照在本地有效期为 60 秒，过期需重新同步。预览后设备或 revision 改变需要重新选择备份预览；提交时腕端也会再次核对 revision。

## 恢复规则

| 模式 | 行为 |
| --- | --- |
| 合并 + 保留现有 | 同 ID 保留腕端记录，新 ID 追加 |
| 合并 + 使用备份 | 同 ID 整条替换为备份记录，新 ID 追加 |
| 替换全部 | 事件集合、排序模式和主事件引用采用备份，移除备份外事件 |

同名不同 ID 是独立事件，不按名称覆盖。合并保留当前排序和主事件；若覆盖后当前主事件变成归档事件，则按既有规则替代或清空。恢复不导入旧 revision，成功提交在当前 revision 上加一；表盘待补写标记由当前同步结果重新生成。

恢复在存储串行队列中单次提交。事件写入失败保留原数据；事件已保存但表盘文件失败时单独提示，不应重复恢复。取消预览不会写入，失败保留预览和编辑草稿，未知结果沿用原请求查询与显式核实。

## 文件格式与预算

农历事件包含原始农历年月日/闰月、对应公历、重复回退规则及 `dm-hko-v1` 表版本，恢复时校验映射一致；未确认相同农历表版本的腕端拒绝恢复含农历的备份。

```json
{
  "format": "daymatter-backup",
  "backupVersion": 1,
  "checksum": "八位十六进制校验值",
  "data": {
    "version": 2,
    "primaryId": "",
    "sortMode": "created",
    "events": []
  }
}
```

只接受受支持版本的备份封装，不直接导入旧数组或任意 `events.json`。完整性校验用于发现内容损坏，不是签名或认证。数字按 IEEE-754 双精度表示归一，对象键按 UTF-16 排序后计算 32 位滚动校验。

- 文件上限 240 KiB（UTF-8），事件最多 200 条，嵌套深度最多 32；不支持原型相关扩展键。
- 稳定 ID、日期、布尔、颜色、枚举和主事件引用均校验；任一条无效会拒绝整份恢复，不跳过后继续。
- 旧长名称可以原样备份恢复，不按新建 50 码点规则截断，但仍有字段接收预算。
- 此备份包含事件数据，不包含背景图片、签名文件或插件未提交草稿。
- 恢复采用单条有界消息，不做分片；真实宿主/设备的最大传输能力仍需验证。

协议能力为 `backupRestore`，还要求稳定 ID、请求身份和保存回执。旧腕端未确认能力时拒绝发送，不降级为逐条新增。
